# uk-legal-mcp v1.1 hardening plan

## Why this exists

After ~3 days exploring a v2 primitive-collapse rebuild on `uk-legal-fleet/feat/v2-rebuild`, ChatGPT dogfeed surfaced workflow failures that the v2 architecture made worse (it dropped `parliament_find_member`, leaving the Pannick lookup unreachable). Root analysis: routing probes (5/6 = 5/6) had been blind to workflow completion. The v1 tool surface was the right shape; what was missing was hardening + description-authority for the ChatGPT cohort + skill workflows for the Claude/Codex cohort.

This plan covers the **v1.1 hardening pass** on the `uk-legal-mcp` repo (Python / FastMCP). Skill work is covered in `uk-legal-plugins/docs/skill-gaps-and-design.md`.

Branch: `feat/hardening-v1.1` off `main`.

## Goals

1. Harden v1's XML parsing (defusedxml at the edge)
2. Adopt `fastmcp.json` declarative config
3. Tool description authority pass for ChatGPT — the only workflow-teaching layer ~80M weekly users see (see `chatgpt-workflow-encoding.md`)
4. Tool annotations per Anthropic mcp-builder guidance
5. Port the genuinely valuable v2 wins (error envelope, audit scripts, spec patches)
6. Deploy + dogfeed verification before merge to main

## What stays unchanged

- **The 27-tool surface across 8 modules** (case_law, legislation, parliament, bills, votes, committees, citations, hmrc). Proven correct via dogfeed — these tools cover the lawyer workflows users need. Reducing or renaming breaks backwards compatibility with the existing 140 skills in `uk-legal-plugins`.
- **The deployment URL** `uk-legal-mcp.fly.dev/mcp`. Atomic in-place replacement of v1 with v1.1. No plugin .mcp.json updates needed.
- **Streamable HTTP transport** on port 8080.
- **The v1 module layout** (`src/modules/{case_law,legislation,...}`).

## Phase A1 — XML safety adapter

**Effort:** ½ day
**Risk:** low (mechanical changes)

### Changes

`pyproject.toml`:
```toml
dependencies = [
    "fastmcp>=3.2.4",
    "lxml>=5.0",
    "defusedxml>=0.7",   # NEW
    "httpx>=0.27",
    "pydantic>=2.0",
]
```

`src/xml_safe.py` (NEW):
```python
"""Single edge adapter for all external XML parsing.

External XML must go through parse_xml() — never call lxml.etree.fromstring()
directly on untrusted content. defusedxml prevents XXE, billion-laughs, and
external-DTD attacks. legislation.gov.uk and TNA Find Case Law are trusted
government sources, but "trusted" doesn't mean immune to upstream compromise,
TLS MITM, or cache poisoning.
"""

from defusedxml.lxml import fromstring as _safe_fromstring
from lxml import etree


def parse_xml(xml_bytes: bytes) -> etree._Element:
    """Parse external XML with XXE / entity-bomb protection.

    Direct calls to lxml.etree.fromstring() on external content are forbidden.
    """
    return _safe_fromstring(xml_bytes)
```

Replace direct `lxml.etree.fromstring()` calls in:
- `src/modules/case_law/parsers.py` (judgment XML)
- `src/modules/case_law/tools.py` (Atom feed parsing — verify location)
- `src/modules/legislation/resources.py` (CLML)
- `src/modules/legislation/tools.py` (CLML — multiple sites; `lxml.html` for HTML stays as-is)

Audit grep for any other `lxml.etree.fromstring` callers and route them through `parse_xml`. `lxml.html.fromstring` for HTML scraping stays — it's a different parser and the same XML attacks don't apply.

### Verification
- `pytest tests/test_citations.py -v` still passes (no XML there, but baseline)
- A live test that fetches a judgment from TNA via `case_law_search` → `judgment_get_paragraph` still works end-to-end (XML still parses)
- Add a unit test asserting `parse_xml` raises on `<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>` content

## Phase A3 — Tool description authority + workflow hints ⭐ CRITICAL

**Effort:** 1-1.5 days
**Risk:** medium (content discipline matters; mechanical churn is low)

This is the load-bearing phase. See `docs/chatgpt-workflow-encoding.md` for the full pattern and 4 worked examples.

### Approach

For each of 27 tools, update the description following the 4-part pattern:
```
1. USE THIS TOOL WHEN ...
2. What it returns
3. AFTER calling this tool, ...
4. Authoritative-source clause
```

### Priority order

Update high-impact tools first; lower-impact tools get the same treatment but second pass.

**Priority 1 — Targets the three confirmed dogfeed failures:**
- `parliament_find_member`
- `parliament_search_hansard`
- `parliament_get_debate_contributions`
- `case_law_search`
- `citations_resolve`
- `citations_format_oscola` (verify v1's actual name — may be `citations_parse` + manual formatting)

**Priority 2 — High-traffic lookups:**
- `legislation_search`
- `legislation_get_section`
- `legislation_get_toc`
- `bills_search_bills`
- `bills_get_bill`
- `votes_search_divisions`
- `votes_get_division`
- `hmrc_search_guidance`

**Priority 3 — Remaining tools:**
- All others — same pattern, lower scrutiny.

### Response envelope shape

Port v2's `_call_provider` envelope from `uk-legal-fleet/servers/uk-legal-mcp/src/primitives/search.py` (the `feat/v2-rebuild` branch). Each tool's response now distinguishes:

```python
{"status": "ok", "data": {...}}
{"status": "empty", "data": [], "next_steps": "..."}
{"status": "upstream_validation", "detail": "..."}
{"status": "upstream_timeout", "detail": "..."}
{"status": "upstream_unavailable", "detail": "..."}
{"status": "auth_required", "detail": "..."}
{"status": "not_found", "detail": "..."}
{"status": "unknown_error", "detail": "..."}
```

This is portable across all 27 tools — write a single helper module `src/envelope.py` and have each tool's `format_http_error()` callsite route through it.

### Verification
- Each tool's `description` field renders correctly under `tools/list`
- `python -m py_compile src/modules/*/tools.py` passes for all modules
- Run the existing live tests; envelope shape change is additive (the `data` field is preserved at the same location), so live tests should keep passing
- Run a fresh ChatGPT dogfeed against the deployed v1.1 — the four target tools should compose into the Pannick / Smith / OSCOLA workflows without external help

## Phase A4 — Tool annotations

**Effort:** ¼ day
**Risk:** low

### Changes

Every `@mcp.tool(...)` decorator gets:
```python
@mcp.tool(
    name="...",
    description="...",
    annotations={
        "readOnlyHint": True,
        "destructiveHint": False,
        "idempotentHint": True,
        "openWorldHint": True,   # False for pure-regex tools like citations_parse
    },
)
```

All current v1 tools are read-only. `openWorldHint=True` for tools that hit external APIs (everything except `citations_parse` which is pure regex over text).

### Verification
- `fastmcp inspect` shows annotations under each tool
- No behavior change

## Phase A6 — Deploy + dogfeed

**Effort:** ½ day
**Risk:** low (atomic deploy to existing URL; rollback via `flyctl releases rollback`)

### Steps

1. **Merge `feat/hardening-v1.1` → `main`** only after all of A1-A5 are verified locally + on a staging Fly app
2. **Staging deploy** to a new app `uk-legal-mcp-v1-1-staging.fly.dev`:
   ```bash
   cd uk-legal-mcp
   flyctl apps create uk-legal-mcp-v1-1-staging
   flyctl deploy --remote-only --app uk-legal-mcp-v1-1-staging
   ```
3. **ChatGPT dogfeed against staging** — run the four prompts:
   - "What did Lord Pannick say about the Renters' Rights Bill in the Lords on 14 October 2025?"
   - "Find Smith v HMRC dealing with VAT recovery and give me the neutral citation."
   - "What does the Pet Abduction Act 2024 say about cat theft?"
   - "Format this as an OSCOLA citation: R v Brown, 1993, House of Lords, [1994] 1 AC 212."
4. **Claude Code dogfeed against staging** — same 4 prompts, with the existing 140 skills loaded
5. **Compare trace shapes:**
   - ChatGPT: should converge on the right tool sequence based on description authority alone
   - Claude: should converge faster / cleaner because skills provide workflow templates
   - Both should report empty/error status honestly; no confabulation
6. **Production deploy** if both dogfeeds pass:
   ```bash
   flyctl deploy --remote-only --app uk-legal-mcp
   flyctl apps destroy uk-legal-mcp-v1-1-staging --yes
   ```
7. **Tear down staging app** (optional — keep around for future hardening releases)

### Acceptance criteria

- All 4 ChatGPT dogfeed prompts complete with correct answers
- All 4 Claude Code dogfeed prompts complete with correct answers
- Zero confabulation events (no fabricated case names / quotes / citations)
- Manchester-landlord-style bypass pattern (16 tool calls + 14 web sources) does not recur
- Existing 140 skills continue to function (sample 3-5 plugins post-deploy)

### Rollback procedure

```bash
flyctl releases --app uk-legal-mcp                  # find prior release
flyctl deploy --image registry.fly.io/uk-legal-mcp@<prior-image> --app uk-legal-mcp
```

The 11 `uk-legal-plugins` keep working through rollback because the URL doesn't change.
